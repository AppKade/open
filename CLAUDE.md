# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AppKade Open (https://open.appkade.lk) is a public, community-contributed repository. It is a static single-page Astro site on Cloudflare Pages that lists AppKade's open-source projects and recognises contributors from their merged GitHub pull requests. The only server code is one Pages Function for anonymous project votes, backed by D1.

## Commits and pull requests

- Commit under the human contributor's own git identity (the configured `user.name`/`user.email`). Never commit as Claude.
- Do not add `Co-Authored-By: Claude …`, `Claude-Session: …` or any other AI attribution trailers to commit messages, and none to PR descriptions.
- Target `main`. Keep each PR focused; contributor points are per merged PR and splitting work to inflate them is against policy (`docs/recognition.md`).

## Commands

Node.js 22.12+ and pnpm 10 (`corepack enable`).

```sh
pnpm install
pnpm dev                              # Astro dev server
pnpm test                             # node --test tests/*.test.mjs
node --test tests/scoring.test.mjs    # a single test file
pnpm check                            # astro check (type checking)
pnpm build                            # static build into dist/
pnpm sync                             # regenerate data/contributors.json + data/activity.json from GitHub (GITHUB_TOKEN optional)
pnpm db:local && pnpm build && pnpm preview   # site + /api/votes with local D1 via wrangler
```

CI (`.github/workflows/ci.yml`) runs `pnpm test`, `pnpm check` and `pnpm build` on every PR; all three must pass.

## Architecture

- **Single page.** All public UI is `src/pages/index.astro` with section anchors (`#projects`, `#contribute`, `#community`) and native `<details>` disclosures. The other files under `src/pages/` only exist to 301-redirect legacy URLs; `public/_redirects` does the same at the edge. Don't add new routes for content that belongs on the homepage.
- **Styling.** `src/styles/open.css` owns all styles (no framework). Several selectors are defined more than once and later rules win, so search the whole file before editing one. Motion must honour both `prefers-reduced-motion` and `html[data-motion="off"]`.
- **Client scripts** live in `src/scripts/` and are imported from `<script>` tags. `motion.ts` drives the starfield canvas, the "Pause motion" toggle (it sets `document.documentElement.dataset.motion`) and reveal animations. `singularity.ts` is the WebGL hero black hole; it watches `data-motion` instead of importing state, and falls back to the CSS hero gradient when WebGL is unavailable. `motion.ts` is a global script, so new scripts must be modules (add `export {}` if nothing else is exported) or `astro check` reports clashing top-level names.
- **Tests run browser code in a VM.** `tests/motion.test.mjs` transpiles `src/scripts/motion.ts`, and `tests/voting.test.mjs` extracts the `<script>` block from `src/components/Vote.astro`; both execute it against hand-written DOM mocks. Changing which DOM APIs those scripts touch usually means updating the mocks.
- **Data is a build-time snapshot.** `src/lib/data.ts` imports the JSON in `data/`. `data/projects.json` is the curated registry (hand-edited, numeric `repoId` required). `data/contributors.json` and `data/activity.json` are generated by `scripts/sync-github.mjs`, which verifies each registry repo through the GitHub API and feeds merged PRs to `src/lib/scoring.mjs`. The committed copies are empty placeholders: the deploy workflow syncs before building and never commits the result, so don't commit sync output.
- **Scoring** (`src/lib/scoring.mjs`, typed by `scoring.d.mts`) is pure and shared by the sync script, the homepage and tests: PR label → points (`type:feature` 10, `type:fix` 8, `type:docs`/`type:test` 5, other 3), +5 for a contributor's first PR, dedupe by `repoId:number`, skip bots and IDs in `data/contributor-optouts.json`. Policy text lives in `docs/recognition.md` and the homepage; keep them in sync with `WEIGHTS`.
- **Voting.** `functions/api/votes/[id].ts` handles `GET|POST|DELETE /api/votes/:repo_id` (only path routed to Functions, see `public/_routes.json`). Mutations require a Turnstile token (`TURNSTILE_SECRET`), a same-origin request and an HMAC-signed visitor cookie (`VOTE_COOKIE_SECRET`); D1 stores only a hashed voter ID. Votes are allowed only for repos in the `published_projects` table.
- **Registering a project** takes two changes: an entry in `data/projects.json` and a new numbered migration in `migrations/` inserting its `repo_id`/`slug` into `published_projects`. Migrations are applied manually (`pnpm db:remote`), never from CI.
- **Deploy.** `.github/workflows/deploy.yml` publishes `main` (on push, daily at 02:15 UTC, and manually) via Wrangler direct upload; there is no Cloudflare Git integration.

## Boundaries

No AppKade accounts, auth provider, admin app or dependency on marketplace databases. Only repositories explicitly listed in `data/projects.json` are published; never auto-discover the organisation's repos. Secrets go in Cloudflare/GitHub settings (see `.env.example`), never in the repo.
