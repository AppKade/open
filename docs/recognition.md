---
title: Contributing and recognition policy
description: How AppKade Open recognizes quality merged GitHub pull requests.
---

Contribution data is generated from public merged GitHub pull requests on explicitly registered, public AppKade repositories. A GitHub user ID is the stable identity; changed usernames don't erase history. No AppKade login is required.

| Primary PR classification | Points |
| :-- | --: |
| `type:feature` | 10 |
| `type:fix` | 8 |
| `type:docs` | 5 |
| `type:test` | 5 |
| Other accepted pull requests | 3 |
| First eligible PR bonus | +5 |

One PR receives only one primary classification. Maintainers manage GitHub issue/PR labels. Pull requests authored by bots, reverted or fraudulent changes, and duplicate submissions may be excluded after review; the exclusion policy will be made public when exercised. Self-merged contributions count when valid, but maintainers cannot inflate scoring through artificial splitting or nonfunctional work.

The all-time board sums eligible contributions; the monthly board uses their actual merged timestamps in UTC. Newcomers are people whose first qualifying merged PR occurred in the past 30 days. Project upvotes, GitHub stars and follower counts **never** count toward contributor points.

Badges are deterministic: **First Contributor** (1 eligible PR), **Active Builder** (3), **Core Contributor** (10). These are community recognitions, not professional endorsements.

For a correction or an opt-out, [open a privacy request](https://github.com/AppKade/open/issues) and provide your GitHub profile. You can request exclusion of your stable GitHub ID from the generated public profiles. Links to your original publicly accessible PRs remain on GitHub.
